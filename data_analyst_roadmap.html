How to build business sense

Business sense = knowing which question matters, not just how to query. It's learnable like any skill.

🧩 The investigation framework (memorize this)

When any metric moves ("sales dropped 15% last month"), walk these steps — this is also the model answer for the most common DA interview question:

StepWhat you doExample
1. ClarifyWhich metric exactly? Compared to what — last month, last year, target?"15% vs last month, or vs same month last year?"
2. Check data firstIs the drop even real? Tracking bug, pipeline failure, missing data?"Did one region's data fail to load?"
3. Segment (MECE)Break by time, region, product, channel, customer type — find WHERE the drop is concentrated"All regions or just South? All products or one category?"
4. Internal causesPrice change, stockout, site outage, campaign ended, UX change"Did the discount season end?"
5. External causesCompetitor move, seasonality, festival timing, economy, weather"Diwali was in this month last year, not this year"
6. Quantify & recommendSize each cause, propose an action, define metric to verify the fix"70% of drop = South stockout → fix supply, track weekly"

🗺️ Frameworks worth knowing (light, not MBA-level)

  • AARRR (Pirate metrics): Acquisition → Activation → Retention → Referral → Revenue. A mental map of any product's funnel.
  • North Star Metric: the ONE metric that best captures product value (Airbnb: nights booked; Spotify: time listening). Ask "what's this company's north star?" for any app you use.
  • MECE segmentation: when splitting data, categories should be Mutually Exclusive, Collectively Exhaustive — no overlap, nothing missed.
  • Correlation ≠ causation: ice cream sales and drownings both rise in summer. Always ask "what third factor could drive both?"

Interview questions you will face

DA intern interviews = SQL live coding + metrics definitions + one "investigate this" case + project walkthrough + basics of Excel/Power BI/stats.

🟦 SQL (live coding — the #1 filter)
Q: Find the 2nd highest salary per department.
DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC), filter rank = 2. Know why RANK vs DENSE_RANK differs with ties.
Q: Month-over-month revenue growth %.
LAG(revenue) OVER (ORDER BY month), then (curr − prev)/prev.
Q: Customers who purchased in Jan but NOT in Feb.
LEFT JOIN + IS NULL, or NOT IN / NOT EXISTS — know all three and the NULL trap in NOT IN.
Q: Remove duplicate rows keeping the latest.
ROW_NUMBER() OVER (PARTITION BY key ORDER BY updated_at DESC) = 1.
Q: Running total of sales by date.
SUM(sales) OVER (ORDER BY date).
Q: WHERE vs HAVING? Order of execution?
WHERE filters rows before grouping, HAVING after. FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.
Q: Types of JOINs + what happens to row counts with duplicates.
INNER/LEFT/RIGHT/FULL/CROSS/SELF; duplicate keys multiply rows — classic gotcha.
🟪 Business case & guesstimates
Q: "App orders dropped 20% this week — investigate."
Use the Tab-3 framework: clarify → data check → segment (platform, city, user type) → internal (app update? payment failures?) → external (competitor offer, holiday) → quantify + recommend. Say the structure OUT LOUD.
Q: "Which metrics would you track for [Zomato / a hospital / an ed-tech app]?"
Pick a north star + 3–4 supporting metrics across the AARRR funnel. For hospital: occupancy, ALOS, readmission, no-show.
Q: "Estimate the number of daily Ola rides in Bengaluru."
Population → % using ride-hailing → rides/user/week → market share. Numbers can be rough; structure must be clean.
Q: "Revenue is up but profit is down. Possible reasons?"
Deeper discounts, shift to low-margin products, rising CAC/logistics costs, returns increase.
Q: "How would you measure the success of a new feature?"
Define success metric BEFORE launch (adoption %, retention lift), compare with control group / pre-post, watch guardrail metrics (crash rate, uninstalls).
🟩 Excel
Q: VLOOKUP vs INDEX-MATCH vs XLOOKUP?
VLOOKUP: only looks right, breaks on column insert. INDEX-MATCH: any direction, robust. XLOOKUP: modern replacement, defaults to exact match.
Q: Absolute vs relative references? ($A$1 vs A1)
$ locks row/column when copying formulas.
Q: What can pivot tables do? What is Power Query?
Pivot: aggregate/slice without formulas. Power Query: repeatable ETL — clean once, refresh forever.
Q: COUNTIF vs COUNTIFS vs SUMPRODUCT?
Single vs multiple conditions; SUMPRODUCT for weighted sums / array-style logic.
🟨 Power BI
Q: Calculated column vs measure?
Column: computed row-by-row at refresh, stored, increases model size. Measure: computed at query time based on filter context. Prefer measures for aggregations.
Q: What is filter context? What does CALCULATE do?
The set of filters active on a calculation (from slicers, rows, visuals). CALCULATE modifies/overrides that context — the most important DAX concept.
Q: Star schema vs one flat table?
Fact table (transactions) + dimension tables (product, customer, date). Faster, cleaner DAX, standard practice.
Q: Import vs DirectQuery?
Import: data copied in, fast, scheduled refresh. DirectQuery: queries source live, real-time but slower.
Q: What is Power Query vs DAX?
Power Query (M): shaping/cleaning BEFORE load. DAX: calculations AFTER load. Clean early, calculate late.
🟥 Statistics & Python
Q: Mean vs median — when does median matter?
With skewed data/outliers (salaries!). Always ask "is this distribution skewed?" 📖 Practical Stats p.25
Q: What is a p-value? What does p < 0.05 mean?
Probability of seeing data this extreme if the null hypothesis were true. Small p → evidence against null. It is NOT "probability the hypothesis is true." 📖 Practical Stats p.121
Q: Explain A/B testing to a non-technical manager.
Show two versions to random user groups, measure the metric, use a statistical test to check the difference isn't luck. 📖 Practical Stats p.106
Q: Correlation vs causation example?
Have one ready (ice cream & drownings → summer). 📖 Practical Stats p.48
Q: pandas — merge vs concat? groupby? how to handle missing values?
merge = SQL-style join; concat = stacking. groupby ≈ GROUP BY. Missing: drop, fill (mean/median/mode), or flag — justify the choice. 📖 McKinney: missing p.221 · merge p.271 · groupby p.338

Which tool in which situation

Interviewers ask this directly ("when would you use Excel vs Power BI?") and it shows maturity.

The real-world pipeline (how companies actually work)

Data lives in a database → SQL extracts & aggregates → pandas/Power Query cleans & transforms → Excel/pandas analyzes ad-hoc → Power BI serves recurring dashboards → You write the insight & recommendation

The analyst's real product is the last step. Tools are just the pipeline.

Excel Use when…

  • Small data (< ~100K rows)
  • Quick one-off / ad-hoc analysis ("check this by EOD")
  • Stakeholder wants to edit or annotate the file
  • Financial models, quick pivots, sanity checks

Avoid when: data is big, task repeats monthly (automate instead), or many people need live access.

SQL Use when…

  • Data lives in a database (it almost always does)
  • Millions of rows — filter/aggregate at the source, never export raw
  • Joining multiple tables
  • A query someone will re-run repeatedly

Rule: push heavy lifting (filters, joins, aggregation) to SQL; bring only the result out.

Power BI Use when…

  • Recurring report (daily/weekly/monthly) — build once, auto-refresh
  • Stakeholders need to self-serve with slicers & drill-downs
  • KPIs must be monitored continuously
  • Combining multiple sources into one model

Avoid when: it's a one-time question (Excel/SQL is faster) or heavy statistics is needed.

pandas / Python Use when…

  • Complex cleaning Excel can't handle (text parsing, fuzzy logic)
  • Statistics: hypothesis tests, correlations, regressions
  • Automation: same analysis on a new file every week → script it
  • Anything heading toward ML (your stage-2 career step)
