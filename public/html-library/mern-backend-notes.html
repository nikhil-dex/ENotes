JavaScript Fundamentals

Loops, Iteration Methods & Function Types
🔄 Loops & Iteration
▼

Classic loop. Best when you need the index or need to break early.

for loop
const arr = [1, 2, 3, 4, 5];

for (let i = 0; i < arr.length; i++) {
  console.log(arr[i]); // 1, 2, 3, 4, 5
}

Cleaner than for loop. Does NOT return a new array. Cannot break out of it.

forEach
arr.forEach((item, index) => {
  console.log(`Index: ${index}, Value: ${item}`);
});

// Returns: undefined — can't chain!

Transforms each element. Always returns a new array of same length.

map
const doubled = arr.map(item => item * 2);
console.log(doubled); // [2, 4, 6, 8, 10]

// Original arr is unchanged!
console.log(arr);     // [1, 2, 3, 4, 5]

Returns a new array with only elements that pass a condition.

filter
const evens = arr.filter(item => item % 2 === 0);
console.log(evens); // [2, 4]

// Combine with map:
const result = arr.filter(n => n > 2).map(n => n * 10);
// [30, 40, 50]

Reduces array to a single value. Takes accumulator + current element.

reduce
const sum = arr.reduce((acc, curr) => acc + curr, 0);
console.log(sum); // 15

// Trace: 0+1=1, 1+2=3, 3+3=6, 6+4=10, 10+5=15

Loops over object keys. Not recommended for arrays.

for...in (objects)
const obj = { name: 'nikhil', age: 21 };

for (let key in obj) {
  console.log(key);        // 'name', 'age'
  console.log(obj[key]);   // 'nikhil', 21
}

Bonus: for...of loops over array values. Cleaner than for...in for arrays.

for...of (arrays)
for (let item of arr) {
  console.log(item); // 1, 2, 3, 4, 5
}

// for...in on arrays gives indexes (0,1,2...) not values!
// Always use for...of for arrays, for...in for objects
💡 Key distinction: for...in → object keys | for...of → array values
⚙️ Function Types
▼

Normal Function

function add(a, b) {
  return a + b;
}

Hoisted — can be called before declaration. Has its own this.

Anonymous Function

const add = function(a, b) {
  return a + b;
};

Not hoisted. Must be assigned to a variable to be used.

Arrow Function

const add = (a, b) => {
  return a + b;
};

// Single param — no parens needed:
const double = a => a * 2;

No own this. Inherits from parent scope.

Implicit Return

// With curly braces — explicit return
const f1 = () => { return 12; };

// No curly braces — implicit return
const f2 = () => 12;

Skip return keyword when there's a single expression.

Asynchronous JavaScript

setTimeout → Callbacks → Promises → Async/Await
📌 JavaScript is single-threaded — it can only do one thing at a time. Async patterns let it handle waiting (network, timers) without blocking.

📈 Evolution of Async Patterns

setTimeout
→
Callbacks
→
Promises
→
async/await

Each solved the problems of the previous approach.

⏱️ setTimeout
▼

Runs code after a delay. Non-blocking — the rest of the code continues executing.

setTimeout example
function showMessage() {
  console.log("hello");           // runs immediately
  setTimeout(() => {
    console.log("nikhil");         // runs after 2 seconds
  }, 2000);
  console.log("this prints first!"); // still runs before timeout
}
showMessage();
// Output: "hello" → "this prints first!" → "nikhil"
📞 Callbacks
▼

Pass a function as an argument to be called when async work is done.

callback pattern
function connectToServer(callback) {
  console.log("connecting...");
  setTimeout(() => {
    console.log("connected!");
    callback(); // call the passed function
  }, 2000);
}

connectToServer(function() {
  console.log("now fetching data...");
});
⚠️ Callback Hell: Nesting callbacks inside callbacks creates messy, hard-to-read "pyramid of doom" code. This is why Promises were invented.
callback hell ← avoid this
connectToServer(function() {
  fetchData(function(data) {
    processData(data, function(result) {
      saveResult(result, function() {
        // 😱 keeps going...
      });
    });
  });
});
🤝 Promises
▼

A Promise is an object that represents a future value. It's either resolved or rejected.

⏳ Pending

Initial state — work in progress

✅ Fulfilled

Success — resolve() was called

❌ Rejected

Failed — reject() was called

promise chaining
function connectToServer() {
  return new Promise((resolve, reject) => {
    setTimeout(() => resolve("connected!"), 2000);
  });
}

function fetchData() {
  return new Promise((resolve, reject) => {
    setTimeout(() => resolve(['data1', 'data2']), 2000);
  });
}

connectToServer()
  .then(response => {
    console.log(response); // "connected!"
    return fetchData();
  })
  .then(data => console.log(data)) // ['data1','data2']
  .catch(err => console.log("Error:", err));
✨ async / await Modern
▼
💡 Your notes didn't cover this — but async/await is the modern standard for writing async code. It's just syntactic sugar over Promises.
async/await — same logic, cleaner code
async function main() {
  try {
    const connection = await connectToServer();
    console.log(connection); // "connected!"

    const data = await fetchData();
    console.log(data);       // ['data1','data2']
  } catch (err) {
    console.log("Error:", err);
  }
}

main();

📤 CommonJS — module.exports & require
▼

Node.js uses CommonJS by default. You export from one file and require in another.

📄 script1.js (exporting)

exporter
function singing(song) {
  console.log(song);
}

// Export single function
module.exports = singing;

// OR export multiple things:
module.exports = { singing, otherFn };

📄 script2.js (importing)

importer
const singing = require('./script1.js');

singing("hello world");
// Output: "hello world"

// If exported as object:
const { singing } = require('./script1.js');
🆕 ES Modules — import / export Modern
▼
💡 ES Modules (ESM) are the modern standard. To use them in Node.js add "type": "module" in package.json.

📄 Exporting

// Named export
export function singing(song) {
  console.log(song);
}

// Default export
export default function main() {}

📄 Importing

// Named import
import { singing } from './script1.js';

// Default import
import main from './script1.js';

📍 IP Address
▼
🔴
Correction in your notes: You wrote "no device has its own ip address / no internet no ip address". This is partially wrong.

Reality: Devices get a private IP from your router (via DHCP) even without internet. The public IP (visible on the internet) is assigned by ISP. So two types of IPs exist simultaneously.

Private IP

Assigned by your router via DHCP. Works within your local network only. e.g. 192.168.1.5

Public IP

Assigned by your ISP via DHCP. Visible on the internet. Changes when you reconnect.

IPv4 vs IPv6
// IPv4 — 32-bit, ~4 billion addresses (running out)
66.94.29.13

// IPv6 — 128-bit, virtually unlimited addresses
2001:0000:3238:DFE1:0063:0000:0000:FEFB
🔒 Proxy, Reverse Proxy & VPN
▼

Proxy (Client-side)

You → Proxy → Server. Hides your identity from the server. Used to bypass blocked sites. But ISP can still read unencrypted data.

Reverse Proxy (Server-side)

You → Reverse Proxy → Server. Protects the server. Handles rate limiting, load balancing, and blocks malicious requests. Example: Nginx, Cloudflare.

VPN

Like a proxy but with encrypted tunnel. Makes you more anonymous. Even ISP can't read the data (unlike regular proxy).

🌐 HTTP Versions
▼
🔴
Correction: Your notes say HTTP/3 "supports TCP/IP and UDP" — this is wrong.

Reality: HTTP/3 uses QUIC protocol, which runs only over UDP. It completely replaces TCP. QUIC was designed by Google to fix TCP's limitations (head-of-line blocking). HTTP/3 does NOT use TCP at all.
VersionTransportKey Feature

🏠 MAC Address, Server, Client & ISP
▼

MAC Address

Physical hardware address burned into your network card. Used to identify devices on a local network (not on the internet). Your router uses MAC to talk to devices on WiFi.

Server

A computer always connected to the internet, programmed to accept requests and send responses. Needs to be always on with powerful hardware.

Client

The device (phone/laptop) that sends requests to servers and receives responses. Your browser is the client when you visit a website.

ISP

Internet Service Provider (e.g., Jio, Airtel). They own and maintain the physical network infrastructure. They assign public IPs, route traffic, and connect users to the global internet.

Node.js Internals

Runtime, Event Loop, Single Thread & LIBUV
✅ Your notes on Node.js are mostly correct! Minor spelling fix: it's Ryan Dahl (not "rayan dhel") who created Node.js.
📖 What is Node.js?
▼

What it IS ✅

A JavaScript runtime environment. Lets JS run outside the browser (on servers, your laptop, etc.).

What it's NOT ❌

NOT a framework (like Express). NOT a library. It's the environment that runs JS code.

🔧 Under the Hood

Your JS Code
→
V8 Engine (C++)
→
LIBUV
→
OS / System

V8 (by Google, written in C++) compiles JS to machine code. LIBUV handles all async I/O operations cross-platform.

🔄 Single Thread & Event Loop
▼

Node.js has ONE main thread, but it's non-blocking — it doesn't wait for slow tasks to finish.

how node handles multiple requests
// Client 1 requests a file (takes 2 seconds)
// Node starts the task → passes to event loop → DOESN'T wait

// Client 2 sends a request immediately after
// Node accepts it and starts processing — doesn't care Client 1 isn't done

// When Client 1's file is ready → event loop sends the response
// Same for Client 2

// 1000 clients? Node handles them all — never blocks!

✅ Node is great for...

Many simultaneous connections (APIs, chat apps, real-time apps) — because I/O is async and non-blocking.

❌ Node struggles with...

CPU-heavy tasks (image processing, ML, video encoding) — these block the single thread and stall all other requests.

💡 Bonus: Node.js v10.5+ added Worker Threads to handle CPU-intensive tasks without blocking the main thread.
🏗️ LIBUV — The Magic Behind Async
▼

LIBUV is a C library that provides Node.js with the ability to handle async I/O across different operating systems.

What LIBUV provides

Event Loop, Thread Pool, Async file system access, Networking (TCP, UDP), Timers, DNS resolution

Thread Pool

LIBUV maintains a pool of threads (default: 4) for operations that can't be done async at OS level, like file I/O and DNS.

⚡ Node.js At a Glance

Created byRyan Dahl (2009)
Built onChrome V8 Engine (C++)
TypeJS Runtime Environment (not framework/library)
Concurrency ModelSingle-threaded + Non-blocking I/O + Event Loop
Async LibraryLIBUV
Best forAPIs, real-time apps, microservices
Bad forCPU-intensive computation

Express Middleware & Packages

morgan · cors · cookie-parser · express-session · connect-flash
⚙️ What is Middleware?
▼

Middleware is a function that runs between the request and the response. It has access to req, res, and next.

Request
→
Middleware 1
→
Middleware 2
→
Route Handler
→
Response
middleware structure
// Global — runs for EVERY request
app.use(function(req, res, next) {
  console.log("runs before every route");
  next(); // must call next() or request hangs!
});

// Route-specific — only runs for /home
app.get("/home", myMiddleware, (req, res) => {
  res.send("home");
});
💡 Key rule: Always call next() in middleware, otherwise the request will hang and the client gets no response.
📦 Common Middleware Packages
▼

morgan Logger

app.use(morgan('tiny'))
// Logs: GET /home 200 12ms

Logs every HTTP request. Use in every project for debugging.

cors Security

// All routes
app.use(cors())

// Single route only
app.get("/", cors(), handler)

Allows your API to be called from other domains (cross-origin).

cookie-parser Cookies

app.use(cookieParser())

// Set a cookie
res.cookie("banned", "true")
// Read a cookie
req.cookies.banned

Parses cookies from request headers into req.cookies.

express-session Session

app.use(expressSession({
  secret: "random",
  resave: false,
  saveUninitialized: false
}))
// Store data
req.session.userId = 123
// Read data
req.session.userId

Stores data server-side per user. Resets on server restart — needs a DB for persistence.

🏷️ Route Params — req.params
▼

Use :paramName in the URL to capture dynamic segments. Access via req.params.

route params
// Single param
app.get("/profile/:username", (req, res) => {
  res.send(req.params.username);
  // URL: /profile/nikhil → "nikhil"
});

// Multiple params
app.get("/profile/:age/:username", (req, res) => {
  const { age, username } = req.params;
  res.send(`name: ${username}, age: ${age}`);
  // URL: /profile/21/nikhil → "name: nikhil, age: 21"
});
🔍 Query Strings — req.query
▼

Query strings come after ? in the URL. Used with GET requests (e.g. search, filters). Access via req.query.

query strings
app.get("/search", (req, res) => {
  console.log(req.query);
  // URL: /search?name=nikhil&age=21
  // req.query → { name: 'nikhil', age: '21' }
});

MongoDB Aggregation

Pipeline operators for filtering & transforming data
✅Your notes on this topic are correct!

🔬 What is Aggregation?

Aggregation processes data through a pipeline of stages. Each stage transforms the data and passes it to the next — like an assembly line for your database queries.

Collection
→
$match
→
$group
→
$project
→
Result
⚙️ Aggregation Operators
▼
OperatorWhat it doesSQL Equivalent
$matchFilter documents by conditionWHERE
$groupGroup documents by a field, compute totals/countsGROUP BY
$lookupJoin/populate data from another collectionJOIN
$projectReshape output — include/exclude/rename fieldsSELECT
$unwindDeconstruct array field into separate documentsUNNEST
$sortSort documentsORDER BY
$limitLimit number of resultsLIMIT
aggregation pipeline example
await userModel.aggregate([
  // Stage 1: filter — only users from Delhi
  { $match: { city: "delhi", isMarried: false } },

  // Stage 2: group — count users per age
  { $group: { _id: "$age", count: { $sum: 1 } } },

  // Stage 3: project — rename/reshape fields
  { $project: { age: "$_id", count: 1, _id: 0 } },

  // Stage 4: sort by count descending
  { $sort: { count: -1 } }
]);
🔗 $lookup — Join Collections
▼

$lookup is the aggregation alternative to populate() — more powerful and flexible.

$lookup example
await postModel.aggregate([
  {
    $lookup: {
      from: "users",        // collection to join
      localField: "user", // field in Post
      foreignField: "_id",// field in User
      as: "userDetails"   // output array name
    }
  }
]);
💥 $unwind — Flatten Arrays
▼
$unwind
// Before $unwind:
// { name: "Nikhil", posts: ["p1", "p2", "p3"] }

// After $unwind: { path: "$posts" }
// { name: "Nikhil", posts: "p1" }
// { name: "Nikhil", posts: "p2" }
// { name: "Nikhil", posts: "p3" }
// Each array element becomes its own document!

🪙 JWT — JSON Web Token
▼

A JWT is a signed token containing user data. The server signs it with a secret — any tampering is detectable.

🔴
Correction in your notes: You used jwt.decode() to verify a token — this is a security bug.

JWT — correct usage
const jwt = require("jsonwebtoken");

);

Express Error Handling

✅ Your notes on this topic are correct!
⚠️ The Problem — Unhandled Errors
▼

Without error handling, if something goes wrong in a route, Express crashes or hangs. We need a way to catch errors and send a clean response.

the problem
app.get("/", (req, res) => {
  res.send(HelloWorld); // ❌ HelloWorld is not defined!
  // Without error handling → server crashes / hangs
});
🔧 The Solution — try/catch + next(err)
▼
error handling pattern
// Step 1: catch error in route, pass to next()
app.get("/", (req, res, next) => {
  try {
    res.send(HelloWorld); // throws ReferenceError
  } catch (err) {
    next(err); // passes error to error handler below
  }
});

// Step 2: error handling middleware — MUST have 4 args
app.use((err, req, res, next) => {
  res.status(500).send(err.message);
});
💡
Important: The error handler middleware must be defined after all your routes — Express identifies it as an error handler because it has exactly 4 parameters (err, req, res, next).

🛡️ Two-Layer Validation
▼

Layer 1 — Mongoose Schema

Validates before saving to DB. Catches basic errors like missing required fields or wrong type.

Layer 2 — Joi

Validates at the route level, before data even reaches the DB. More powerful rules (email format, regex, etc.).

models/user.js — both layers
const mongoose = require("mongoose");
const Joi = require("joi");

// Layer 1: Mongoose schema validation
const userSchema = new mongoose.Schema({
  name:     { type: String, required: true, minlength: 3 },
  email:    { type: String, required: true },
  password: { type: String, required: true, minlength: 3 },
});

// Layer 2: Joi validation function
function validator(data) {
  let schema = Joi.object({
    name:     Joi.string().min(3).required(),
    email:    Joi.string().email().required(),
    password: Joi.string().min(3).required(),
  });
  let { error } = schema.validate(data);
  return error; // undefined if valid, error object if invalid
}

let userModel = mongoose.model("User", userSchema);
module.exports = { userModel, validator };
using validator in route
app.post("/create", async (req, res) => {
  let { name, email, password } = req.body;
  let error = validator({ name, email, password });
  if (error) return res.status(400).send(error.details[0].message);
  // data is valid — proceed to save
  res.send("valid");
});

⚖️ Embedding vs Referencing
▼

Embedding ❌ (avoid for large data)

  { content: "post 1" },

❓ What & Why Redis?

Redis is an in-memory key-value store. It's blazing fast because data lives in RAM, not on disk. Use it to cache expensive DB queries so repeated requests don't hit MongoDB every time.

🔌 Connect & Basic Commands
▼
setup & commands
const redis = require("redis");

const client = redis.createClient({
  socket: { host: "your-redis-host", port: 14918 },
  username: "default",
  password: "your-password"
});
await client.connect();

// SET — store a value
await client.set("user:profile:n@gmail.com", JSON.stringify(user));

// SET with expiry — auto-delete after N seconds
await client.setEx("user:profile:n@gmail.com", 5, JSON.stringify(user));

// GET — retrieve a value
const cached = JSON.parse(await client.get("user:profile:n@gmail.com"));

// DEL — delete a key
await client.del("user:profile:n@gmail.com");
📌 Redis only stores strings. Always JSON.stringify() objects before storing and JSON.parse() when reading.
🔧 Correct Caching Pattern
▼
🔴
Bug in your notes: Your code always queries MongoDB even when cache exists. The correct pattern is: check cache first → return if found → only query DB on miss.
correct caching pattern
app.get("/users/:emailId", async (req, res) => {
  const cacheKey = `user:profile:${req.params.emailId}`;

  // Step 1: Check Redis first
  const cached = await client.get(cacheKey);
  if (cached) {
    console.log("Cache HIT ⚡");
    return res.send(JSON.parse(cached)); // return early, skip DB
  }

  // Step 2: Cache miss — query DB
  console.log("Cache MISS 🐌");
  const user = await userModel.findOne({ email: req.params.emailId });
  if (!user) return res.send("user not found");

  // Step 3: Store in Redis for next time (expires in 5s)
  await client.setEx(cacheKey, 5, JSON.stringify(user));
  res.send(user);
});

client.get(key)Retrieve value (null if missing/expired)

WebSocket — Socket.io

Real-time bidirectional communication
✅Your notes on this topic are correct!
❓ HTTP vs WebSocket
▼

HTTP (normal)

Client asks → Server answers → Connection closed. One-way, request-response. Server can't push data without a request.

WebSocket (Socket.io)

Persistent two-way connection. Server can push data to client anytime. Perfect for chat, live updates, games.

🔧 Server Setup
▼
app.js — server side
const http = require("http");          // built-in
const socketIo = require("socket.io"); // npm i socket.io

const server = http.createServer(app); // wrap express in http server
const io = socketIo(server);          // attach socket.io to server

// Listen for new connections
io.on("connection", (socket) => {
  console.log("User connected:", socket.id);

  socket.on("connectToServer", () => {
    console.log("client triggered event");
  });

  socket.on("disconnect", () => {
    console.log("User disconnected:", socket.id);
  });
});

server.listen(3000); // use server.listen, NOT app.listen!
💻 Client Setup (EJS/HTML)
▼
index.ejs — client side
<!-- Load socket.io from CDN -->
<script src="https://cdn.socket.io/3.1.3/socket.io.min.js"></script>

<script>
  var socket = io(); // auto-connects to server

  // Send event to server
  document.getElementById("btn").addEventListener("click", () => {
    socket.emit("connectToServer");
  });

  // Disconnect
  document.getElementById("btnd").addEventListener("click", () => {
    socket.disconnect();
  });
</script>
📡 Emit Cheatsheet — io vs socket
▼
✅ Your note was exactly right: "send message to multiple users use io, send message to one user use socket"
CodeWho receives it
socket.emit("event")This client only
io.emit("event")ALL connected clients
socket.broadcast.emit("event")Everyone EXCEPT this client
socket.join("room")Join a room (group)
io.to("room").emit("event")Everyone in a room
typing indicator example
// Server
io.on("connection", (socket) => {
  socket.on("typing", () => {
    socket.broadcast.emit("typing"); // tell everyone else
  });
});

// Client
socket.emit("typing");           // send to server when typing
socket.on("typing", () => {
  console.log("someone is typing...");
});

💬 WebSocket Chat App

Socket.io Practice T28

A real chat app — putting T27 theory into practice. Key difference: create an http server from Express, then attach Socket.io to it. Use server.listen(), not app.listen().

🖥️ Server Code
▼
app.js
const express = require("express");
const http     = require("http");
const socketIo = require("socket.io");
const app      = express();

const server = http.createServer(app); // wrap Express
const io     = socketIo(server);      // attach Socket.io

io.on("connection", (socket) => {
  socket.on("Join", (data) => {
    io.emit("take", `${data} received`); // broadcast to ALL
  });
});

server.listen(3000); // server.listen — NOT app.listen
💻 Client Code (EJS)
▼
index.ejs
<!-- Socket.io auto-serves its client library -->
<script src="/socket.io/socket.io.js"></script>
<script>
  const socket = io(); // connects to same server

  // Send
  socket.emit("Join", messageValue);

  // Receive broadcast
  socket.on("take", (data) => {
    console.log(data);
  });
</script>
✅ No separate client install — Socket.io serves its JS automatically at /socket.io/socket.io.js.

📐 RESTful API Design

REST Principles T31

REST = Representational State Transfer. A set of conventions for designing predictable APIs. The HTTP method IS the action — URLs should be nouns, not verbs.

🔑 HTTP Methods → CRUD
▼
MethodCRUDURL ExampleWhat it does
GETReadGET /usersFetch all users
GETRead oneGET /users/:idFetch one user
POSTCreatePOST /usersCreate a user
PUTReplacePUT /users/:idReplace entire user
PATCHUpdatePATCH /users/:idUpdate specific fields
DELETEDeleteDELETE /users/:idDelete user
📝 URL Design Rules
▼
❌ Wrong✅ REST
/getUsersGET /users
/createUserPOST /users
/deleteUser?id=5DELETE /users/5
/user/5/getPostGET /users/5/posts
  • Use nouns not verbs — HTTP method is the verb
  • Use plural: /users not /user
  • Use nesting for relationships: /users/:id/posts
  • Stateless: each request must be self-contained, server stores no session

💳 Razorpay Payment

Payments T32

Razorpay lets you accept payments in INR. Flow: backend creates an order → frontend opens checkout popup → payment → backend verifies the signature to confirm it's legit.

⚙️ Setup
▼
install + init
npm install razorpay

const Razorpay = require("razorpay");
const razorpay = new Razorpay({
  key_id:     process.env.RAZORPAY_KEY_ID,     // public — OK to send to frontend
  key_secret: process.env.RAZORPAY_KEY_SECRET  // private — NEVER send to frontend
});
📋 Full Flow
▼
Step 1 — Backend: Create Order
router.post("/create-order", async (req, res) => {
  const order = await razorpay.orders.create({
    amount: req.body.amount * 100, // ⚠️ paise! 1 INR = 100 paise
    currency: "INR"
  });
  // Save to DB with status "pending"
  await Payment.create({ orderId: order.id, amount: order.amount, status: "pending" });
  res.json({ success: true, order });
});
Step 2 — Frontend: Open Checkout
// Load: <script src="https://checkout.razorpay.com/v1/checkout.js">
const options = {
  key:      "<%= key %>",      // KEY_ID passed from backend via EJS
  amount:   order.amount,      // already in paise
  order_id: order.id,
  handler: async function(response) {
    // Called on payment success — send to backend for verification
    await fetch("/api/payment/verify-payment", {
      method: "POST",
      body: JSON.stringify({
        razorpayOrderId:   response.razorpay_order_id,
        razorpayPaymentId: response.razorpay_payment_id,
        razorpaySignature: response.razorpay_signature
      })
    });
  }
};
new Razorpay(options).open();
Step 3 — Backend: Verify Signature
const crypto = require("crypto");

const body              = razorpayOrderId + "|" + razorpayPaymentId;
const expectedSignature = crypto
  .createHmac("sha256", process.env.RAZORPAY_KEY_SECRET)
  .update(body)
  .digest("hex");

if (expectedSignature === razorpaySignature) {
  // Payment confirmed — update DB status to "completed"
  await Payment.findOneAndUpdate({ orderId: razorpayOrderId }, { status: "completed", paymentId: razorpayPaymentId });
  res.json({ success: true });
} else {
  res.status(400).json({ success: false, message: "Invalid signature" });
}

🚪 Logout — Token Blacklisting
▼

JWT can't be "deleted" server-side normally. Solution: store logged-out tokens in a MongoDB blacklist collection and reject any blacklisted token.

Logout controller
const token = req.headers.authorization.split(" ")[1];
await blacklistModel.create({ token }); // blacklist it
res.json({ message: "Logged out" });

// Auth middleware checks this on every request:
const isBlacklisted = await blacklistModel.findOne({ token });
if (isBlacklisted) return res.status(401).json({ message: "Unauthorized" });

🌐 CORS

Security Bonus

CORS = Cross-Origin Resource Sharing. Browsers block requests to a different origin (protocol + domain + port) by default — CORS headers tell the browser it's allowed.

❓ Why Does It Happen
▼

React on localhost:3000 calls Express on localhost:5000 — different ports = different origins → browser blocks it. Postman is NOT a browser, so it's never affected by CORS.

⚠️ CORS is a browser security restriction only. API calls from Postman, curl, or server-to-server always work regardless of CORS.
💻 Using the cors Package
▼
app.js
npm install cors

const cors = require("cors");

// Option 1: Allow all origins (quick, not for production)
app.use(cors());

// Option 2: Specific config (production)
app.use(cors({
  origin:      "https://your-react-app.vercel.app",
  methods:     ["GET", "POST", "PUT", "DELETE"],
  credentials: true  // needed if sending cookies or auth headers
}));
💡 If credentials: true on backend, React must also send { withCredentials: true } per axios request (or set axios.defaults.withCredentials = true globally).

🛡️ Rate Limiting

Security Bonus

Prevents abuse — like someone making 1000 login attempts per second (brute force). Use express-rate-limit.

💻 Setup
▼
app.js
npm install express-rate-limit

const rateLimit = require("express-rate-limit");

// Global: max 100 requests per 15 minutes per IP
app.use(rateLimit({
  windowMs: 15 * 60 * 1000, // 15 min in ms
  max:      100,
  message:  { error: "Too many requests, try again later" }
}));

// Stricter for login: only 5 attempts per minute
const loginLimiter = rateLimit({ windowMs: 60000, max: 5 });
app.use("/user/signin", loginLimiter);

📄 Pagination

MongoDB Bonus

Load data in chunks instead of all at once. Uses Mongoose's .skip() and .limit().

💻 Pattern
▼
Controller
// Client sends: GET /posts?page=2&limit=10
const page  = parseInt(req.query.page)  || 1;
const limit = parseInt(req.query.limit) || 10;
const skip  = (page - 1) * limit; // key formula

const data  = await Model.find({}).skip(skip).limit(limit);
const total = await Model.countDocuments({});

res.json({
  data,
  currentPage: page,
  totalPages:  Math.ceil(total / limit),
  total
});

🚀 Deployment

DevOps Bonus

Deploy Express backend to Render.com, React frontend to Vercel, database to MongoDB Atlas — all free tier.

📋 Render.com — Deploy Express
▼
  1. Push code to GitHub — make sure .env is in .gitignore
  2. Sign up at render.com → New → Web Service → Connect GitHub repo
  3. Build Command: npm install
  4. Start Command: node app.js (or npm start)
  5. Add all env vars in Render dashboard (PORT, MONGO_URI, JWT_SECRET, etc.)
  6. Deploy → you get a URL like https://your-app.onrender.com
⚠️ Free tier spins down after 15 min of inactivity. First request after spin-down takes ~30 seconds. This is normal for free hosting.
🗄️ MongoDB Atlas
▼
  1. Go to mongodb.com/atlas → Create free cluster (M0)
  2. Database Access → Add user + password
  3. Network Access → Add IP 0.0.0.0/0 (allow all — needed for Render)
  4. Connect → Drivers → Copy connection string
  5. Replace <password> → paste as MONGO_URI in Render env vars
MONGO_URI format
mongodb+srv://username:password@cluster0.xxxxx.mongodb.net/dbname?retryWrites=true&w=majority
⚛️ React → Vercel
▼
  1. Push React app to GitHub
  2. Go to vercel.com → Import repo → Vercel auto-detects CRA/Vite
  3. Add env var: REACT_APP_API_URL = https://your-app.onrender.com
  4. Replace all hardcoded localhost:PORT API URLs with process.env.REACT_APP_API_URL
💡 After deploying backend, update CORS on Express to allow your Vercel domain: cors({ origin: "https://your-app.vercel.app" })
